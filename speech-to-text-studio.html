01 CONTEXT
THE PROBLEM

What needed to work better?

A useful speech workflow needs to handle browser microphone and speech-recognition support, keep transcript edits reliable, and protect the OpenAI API key from frontend exposure.

THE SOLUTION

A focused product experience

Speech to Text Studio combines browser recording and transcription with an Express backend for OpenAI requests. Users can edit and save transcripts, then download them or generate a summary.

KEY FEATURES

Designed around useful tasks

01

Record and transcribe

Use browser microphone access and the Speech Recognition API to turn spoken input into a transcript.

02

Summaries and action items

Send transcript content through the backend for AI-generated summaries, key points and action items.

03

Edit, save and download

Keep transcript editing in the workflow, save transcripts and download the finished text with clear status feedback.

TECHNICAL CHALLENGE

Support browser speech features while keeping transcript state reliable and API credentials private.

APPROACH

The browser handles microphone and speech recognition, while OpenAI requests go through a Node.js and Express backend so the API key is not exposed in frontend code.

03 RESULTS & TAKEAWAYS
WHAT IT DELIVERS

From idea to usable experience

The app provides transcription, editable transcripts, transcript downloads, AI summaries and responsive layouts with success, warning and error feedback.

PROJECT TAKEAWAYS
  • The workflow combines browser-native speech features with a backend AI call.
  • Transcript editing and saving are part of the same user flow.
  • The backend keeps the OpenAI API key out of frontend code.
